## 3. Реализованные алгоритмы

### 3.1. Быстрая сортировка

Используется случайный выбор опорного элемента и схема Хоара.

Для ограничения глубины стека рекурсивно обрабатывается меньшая часть массива, а большую часть алгоритм продолжает обрабатывать в цикле. Поэтому глубина рекурсии ограничивается величиной порядка `O(log n)` при сбалансированных разбиениях.

Теоретическая сложность:

- лучший случай: `Θ(n log n)`;
- средний случай: `Θ(n log n)`;
- худший случай: `Θ(n²)`;
- дополнительная память: `O(log n)` для стека при используемом приёме;
- сортировка не является устойчивой.

### 3.2. Восходящая сортировка слиянием

Используется итеративная bottom-up версия без рекурсии. Сначала сливаются блоки длины 1, затем 2, 4, 8 и т. д.

Теоретическая сложность:

- лучший случай: `Θ(n log n)`;
- средний случай: `Θ(n log n)`;
- худший случай: `Θ(n log n)`;
- дополнительная память: `Θ(n)`;
- сортировка устойчивая.

### Проверка `T(2n)/T(n)`

Для `O(n log n)`:

`T(2n)/T(n) ≈ 2 * log₂(2n) / log₂(n)`.

Эксперимент 1 показывает различие между квадратичными алгоритмами ЛР №2 и алгоритмами класса `O(n log n)`. При увеличении размера массива разница во времени становится заметной: Quick Sort и Merge Sort растут значительно медленнее.

В эксперименте 3 случайный pivot делает Quick Sort менее чувствительной к исходной упорядоченности R/S/V/N, чем вариант с фиксированным первым или последним pivot. Merge Sort также имеет `Θ(n log n)` для всех этих типов входа.

Встроенная `sorted()` обычно оказывается существенно быстрее учебных реализаций, поскольку выполняется внутри CPython и использует высокооптимизированную реализацию. Поэтому в прикладной программе при отсутствии специальных требований предпочтительно использовать стандартную сортировку Python.

| Алгоритм | Лучший | Средний | Худший | Память | Устойчивость |
|---|---|---|---|---|---|
| Пузырьком | `Θ(n)` | `Θ(n²)` | `Θ(n²)` | `O(1)` | Да |
| Вставками | `Θ(n)` | `Θ(n²)` | `Θ(n²)` | `O(1)` | Да |

`*` Для Python Timsort/Powersort лучший случай зависит от структуры входных runs.

## 15. Контрольные вопросы

### 1. Три этапа «разделяй и властвуй» на примере Merge Sort

**Разделение:** массив делится на две части.  
**Властвование:** каждая часть сортируется отдельно.  
**Комбинирование:** две отсортированные части сливаются в один упорядоченный массив.

### 2. Рекуррентное соотношение Merge Sort

`T(n) = 2T(n/2) + Θ(n)`.

На каждом уровне дерева рекурсии суммарно выполняется `Θ(n)` работы, а число уровней равно `Θ(log n)`. Поэтому `T(n) = Θ(n log n)`.

### 3. Почему сортировка сравнением требует Ω(n log n)?

Существует `n!` возможных перестановок элементов. Дерево сравнений должно различать эти варианты. Его высота не может быть меньше `log₂(n!)`, а по формуле Стирлинга `log₂(n!) = Ω(n log n)`.

### 4. Худшие данные для Quick Sort с pivot «первый»

Уже отсортированный и обратно отсортированный массивы. Первый элемент оказывается минимумом или максимумом, поэтому одно из подмножеств имеет размер `n-1`, а другое — 0. Возникает `T(n)=T(n-1)+Θ(n)=Θ(n²)`.

### 5. Отличие Ломуто и Хоара

Ломуто использует один основной указатель и обычно последний элемент как pivot. Хоара использует два указателя, движущихся навстречу. Хоара обычно выполняет меньше обменов.

### 6. Как рандомизация защищает от худшего случая?

Она делает выбор pivot независимым от заранее известной структуры входа. Для фиксированного входа вероятность систематически получать крайне неудачные разбиения становится малой; ожидаемое время остаётся `Θ(n log n)`.

### 7. Почему Quick Sort часто быстрее Merge Sort?

Quick Sort может работать почти полностью внутри исходного массива и обычно выполняет мало дополнительных операций с памятью. У Merge Sort есть расходы на буфер и копирование при слиянии.

### 8. Как ограничить глубину рекурсии Quick Sort до O(log n)?

На каждом шаге рекурсивно обрабатывать меньшую часть, а большую обрабатывать циклом. Даже если разбиения неидеальны, глубина стека ограничивается размером меньшей рекурсивной части.

### 9. Почему Merge Sort устойчив, а Quick Sort — нет?

В Merge Sort при равных ключах можно выбирать элемент из левой части первым, сохраняя исходный порядок равных элементов. В обычном Quick Sort обмены при разбиении могут менять порядок равных элементов.

### 10. Что лежит в основе Timsort?

Timsort использует уже существующие упорядоченные участки (runs), сортировку вставками для небольших участков и эффективное слияние. Это позволяет хорошо работать на частично упорядоченных данных.

### 11. Как сортировать 10 млн транзакций при недостатке ОЗУ?

Использовать внешнюю сортировку: данные разбиваются на части, каждая часть сортируется и сохраняется во внешнее хранилище, после чего отсортированные части многопутево сливаются.
